# Report Schema

`scripts/render-report.ps1` accepts UTF-8 JSON and renders one offline HTML report. Keep the schema stable so audit runs can be compared across versions.

## Top-level shape

```json
{
  "schemaVersion": "2.2",
  "project": "Project name",
  "repository": "F:\\path\\to\\repo",
  "auditTime": "2026-05-27 15:30:00",
  "scope": ["源代码", "构建文件", "依赖清单", "测试目录"],
  "auditor": "Codex",
  "config": {
    "loaded": true,
    "path": "F:\\repo\\audit-config.yml",
    "languages": ["C++"],
    "changedOnly": false,
    "diffBase": "",
    "diffTarget": "HEAD",
    "minScore": 0,
    "failOnHigh": false,
    "scaEnabled": true,
    "sbomEnabled": true
  },
  "reportOptions": {
    "redacted": false,
    "generatedBy": "code-audit-report"
  },
  "summary": {
    "score": 82,
    "rating": "良好",
    "riskLevel": "中",
    "conclusion": "总体可用，但存在需要优先整改的安全和可靠性问题。"
  },
  "stats": {
    "total": 11,
    "active": 11,
    "high": 1,
    "medium": 3,
    "low": 5,
    "review": 2,
    "open": 11,
    "accepted": 0,
    "falsePositive": 0,
    "fixed": 0
  },
  "inventory": {},
  "diff": {},
  "baseline": {},
  "sca": {},
  "dimensionScores": [],
  "findings": [],
  "roadmap": [],
  "tools": [],
  "limitations": []

```

Required fields: `project`, `repository`, `auditTime`, `summary`, `findings`.

## Configuration and options

`config` records the effective runtime options after merging command-line arguments and `audit-config.yml`. `reportOptions.redacted` indicates whether path/IP redaction was applied to the JSON and HTML output.

## Incremental audit

```json
{
  "enabled": true,
  "available": true,
  "base": "origin/main",
  "target": "HEAD",
  "changedFileCount": 8,
  "auditedChangedSourceFileCount": 6,
  "reason": "",
  "files": ["src/main.cpp"]
}
```

When `available` is `false`, the audit falls back to full inventory and records the reason.

## Baseline

```json
{
  "enabled": true,
  "path": "F:\\repo\\.audit-baseline.json",
  "matched": 2,
  "falsePositive": 1,
  "accepted": 1,
  "fixed": 0,
  "missing": 0,
  "exportedPath": ""
}
```

Baseline statuses come from `references/false-positive-handling.md`. `false_positive` and `fixed` are excluded from active statistics and scoring; `accepted` remains visible and scored but is exempt from the `-FailOnHigh` gate.

## Dimension score

```json
{
  "dimension": "安全性",
  "weight": 20,
  "score": 16,
  "summary": "发现 2 个相关问题，需按优先级整改。"
}
```

Recommended dimensions:

- 架构合理性
- 功能正确性
- 编码规范性
- 安全性
- 可靠性/健壮性
- 可维护性/可演进性
- 性能与资源
- 可观测性与运维性
- 测试质量
- 依赖与供应链风险

## Finding

```json
{
  "id": "F-001",
  "ruleId": "CPP-SEC-001",
  "title": "外部命令通过字符串拼接执行，存在命令注入风险",
  "severity": "高",
  "dimension": "安全性",
  "priority": "P0",
  "confidence": "高",
  "confidenceReason": "命中 std::system，且命令字符串包含变量拼接。",
  "location": "src/log_export/exporter.cpp:40",
  "evidence": "src/log_export/exporter.cpp:40 => std::system(cmd.c_str());",
  "impact": "异常输入可能改变命令语义，导致任意命令执行或越权访问。",
  "recommendation": "改用参数数组执行接口，并对工具路径和输出目录做白名单校验。",
  "fixExample": "boost::process::child child(toolPath, boost::process::start_dir = slotDir.string());",
  "source": "heuristic",
  "cwe": "CWE-78",
  "owasp": "A03:2021 Injection",
  "affectedComponent": "日志导出",
  "remediationEffort": "中",
  "fingerprint": "e3a1f66aa5bb3310",
  "status": "open",
  "baselineReason": "",
  "baselineOwner": ""
}
```

Allowed values:

- `severity`: `高`, `中`, `低`, `待复核`
- `priority`: `P0`, `P1`, `P2`, `P3`
- `confidence`: `高`, `中`, `低`
- `source`: `manual`, `tool`, `heuristic`, `model`
- `status`: `open`, `fixed`, `accepted`, `false_positive`

Quality requirements:

- Every finding must include specific evidence.
- Tool findings must be reviewed before entering final report.
- Unconfirmed concerns use severity `待复核` and explain missing evidence.
- Similar findings should be grouped by root cause and keep a stable `fingerprint`.
