# Go 审计规范要点

参考 Go 官方 Code Review Comments、Effective Go、OWASP、CWE 和云厂商服务端工程实践。重点关注：

| 维度 | 检查点 |
|---|---|
| 安全性 | SQL/命令/模板注入，路径穿越，SSRF，弱随机数，硬编码密钥，JWT/Session 校验缺失 |
| 可靠性 | `context.Context` 传递与超时取消，goroutine 泄漏，channel 关闭约定，panic 边界，错误返回处理 |
| 编码规范 | 包名短小一致，导出符号注释，错误包装 `%w`，避免全局可变状态，表驱动测试 |
| 性能资源 | HTTP/DB 连接池，响应体关闭，锁粒度，切片扩容，大对象复制，热路径反射 |
| 可维护性 | 分层边界、接口定义位置、配置注入、可测试性、日志字段规范 |

高优先级规则：

- 禁止拼接 SQL、shell 命令、文件路径后直接执行。
- 所有外部 I/O 必须有超时、取消和错误上下文。
- goroutine 必须有退出条件；长期后台任务要有生命周期管理。
- `defer resp.Body.Close()`、文件句柄、事务和锁释放必须可证明。
- 敏感信息不得写入日志或配置仓库。
